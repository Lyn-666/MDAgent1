**Research goal as redefined by the user (2026-11-20, most important, said in another session):** The project is not a workflow that "stops when the sampling target is reached". It is **getting results that agree with a high-budget reference, at a given precision, for the least compute** (accuracy-constrained simulation budget optimization). The question: given a system, a quantity to measure and a budget, can the agent itself allocate simulation time, number of replicas and sampling strategy, and get a statistically reliable result at minimum cost? It applies to two kinds of task: (1) plain MD: how many ns, how many replicas, when it can stop early; (2) adaptive sampling: when to start new replicas, from which conformation to restart, how long each runs, how to split the remaining budget. Note that adaptive sampling is not enhanced sampling. Do allocation and restarts for unbiased MD first; it is easier to verify that the equilibrium quantities are correct.

## Code structure

The code is in `mdagent/`; the full workflow is described in the "Full workflow (in order)" section of `docs/developer.md`.

- `fetch.py`: downloads by PDB ID from RCSB to `structures/<ID>.pdb`.
- `check.py`: structure check before system setup. When the reference sequence is not available (download failed or the UniProt entry is obsolete), it does not judge tags and does not delete any residue; for an obsolete entry it lists replacement IDs; `--uniprot` can replace the ID in the file. It compares position by position against DBREF/SEQADV and UniProt (including isoforms, cached in `structures/uniprot/`); it finds tags, multiple copies, metals, terminal caps, unknown residues, long gaps and chain breaks; it decides for each chain end whether to add a cap.
- `build.py`: system setup (PDBFixer). Chain selection, tag removal, capping (in CHARMM the cap is merged into the terminal residue as a patch; in Amber it is a separate residue), protonation, water and ions. `load_amber` reads a user-prepared Amber system as it is (ligands kept).
- `protonation.py`: PROPKA and manual protonation.
- `simulate.py`: runs MD in segments, can continue; `equilibrate` is the staged equilibration.
- `diagnose.py`: side-chain chi1 diagnosis and ranking. Prolines and cysteines in disulfide bonds (judged by SG-SG distance) are classed as `fixed_chi1` and skipped. `agent.py`: the multi-round loop; decides to continue or stop; `run_all` runs enhanced sampling automatically after plain MD.
- `enhanced.py`: well-tempered metadynamics on dihedrals (chi1; for backbone φ/ψ, two per residue), implemented in OpenMM. It biases at most `max_residues` (default 10, `--enhanced-max-residues`) of the slowest side chains at a time. The replicas run in turns, 1 ns per turn.
- `reweight.py`: replays the Gaussian hills to rebuild the bias potential, Tiwary-Parrinello reweighting, computes state populations and errors; `assess` classes each side chain as reached / stalled / unreliable / not_yet; `populations.json`. Tested with a model of known populations and a model of two coupled side chains.
- `uncertainty.py`: block-averaging errors (accounts for time correlation), combining replicas, effective sample size, t-distribution factors (`t_factor`, `Precision.factor(df)`), automated equilibration detection (`statistical_inefficiency`, `equilibration_start`), error floor (by number of transitions for plain MD, by effective sample size for enhanced sampling). Used by both plain MD and enhanced sampling. Also `Precision` (tolerance + criterion + α + number of looks; `met()` decides whether it is precise enough) and `planned_looks()` (number of looks = budget ÷ length per round). `judge` and `reweight.assess` both accept a `Precision` or a float (old behavior).
- `cost.py`: compute cost. `of()` computes from the length of each replica; `of_run()` computes from `run.json` (enhanced sampling continues from plain MD and does not pay equilibration time again); `reduction()` compares two costs.
- `budget.py`: strategy comparison (replay). `Pool` (per-frame states of each replica), `pool_from_run()` (reads a finished run; supports chi1 and distances), `markov_pool()` (model with known populations; no GPU needed), `replay()` (runs one strategy once), `reference()` (independent reference: true value or unused replicas), `check_against()` (accurate = really within the tolerance; equivalent = proven by TOST), `compare_strategies()` (many repeats), `write()`. Four strategies: fixed / early_stop / add_replicas / mdagent. **The rules of the mdagent strategy mirror the rules in `policy.py`**; when you change the rules in `policy.py`, change `budget._decide` too. Both sides share `policy.spread_labels` and `policy.stalled_labels`.
- `scripts/budget_experiment.sh`: general strategy comparison (data pool + replay of four strategies, three criteria).
- `allocation.py`: the agent's allocation and stop rules (`next_step`, `allocate`), shared by daily runs and Experiment A. `landscape.py`: φ/ψ free-energy maps.
- `basins.py`, `experiment_a.py`, `scripts/experiment_A.sh`: backbone basins and Experiment A (see "Experiment A" and "Review comments and revisions" above). `basins.trim` (burn-in), `basins.state_factors` (z or t for each basin); `experiment_a.FAMILIES`/`family_pool` (four kinds of synthetic models), `run_pilot_fixed`, `sensitivity`. `--fixed-grid`, `--baseline`, `--holdout`, `--items`, `--target-rate` of `budget` and `hypothesis_a()` are the approach of the previous version of Experiment A and can still be used for general comparisons.
- Goal, precision criterion (`criterion`, `alpha`) and permissions are in `agent.Goal` (`goal` in `run.json`); `RunState.precision()` assembles them into a `Precision`. The stop reasons target_reached / stalled / budget_exhausted / failed are recorded in `run.json` (`notes.plain_md_outcome`, `enhanced.outcome`, and `notes.outcome` on failure).
- `messages.py`: messages that a run sends to the chat.
- `policy.py`: step 4; after each round it chooses the next action (stop, extend, add replicas and catch them up, extend beyond the budget, suggest reseeding, stop early when the target is not reachable within the limits), checking permissions first. Without permission it makes a suggestion in the chat and says how to confirm. Recorded in `notes.actions` in `run.json`. The equivalent rules for enhanced sampling are in the loop of `agent.run_all`. Cost-based allocation uses `allocation_next` (`allocation.py`).
- `report.py`: step 6; at the end of a run it writes `report.zh.md` and `report.en.md` (conclusion, errors, cost, stop reason, actions, limitations, files, open issues). `equivalent()` is the equivalence test (TOST); `compare` uses it to decide whether two runs give the same answer (the tolerance defaults to the precision required by the compared run; change it with `--tolerance`). Commands `report`, `compare`, `budget`.
- `scripts/step5_validation.sh`: the step 5 scenarios to run on the GPU (target reached, trapped, budget exhausted, enhanced sampling, plus a reference run), summarized in `runs/val_<protein>_summary.txt`. Default is 1UBQ (the user asked to replace 181L as the main example; `--uniprot P0CG48 --termini charged`); 181L also works.
- `observables.py`: the result-quantity layer. Each quantity becomes per-frame states, and then uses the same diagnosis, errors and stop judgment. Also the goal "see a given change" (`EventSpec`, `first_entry`, `diagnose_events`). `chi1` (g+/t/g-) and `distance` (near/far, `A:88:OH-A:111:CG1@0.6`, with a ±0.05 nm buffer around the threshold). `--quantity`, `--distances`; in the chat, `target_kind` is `distance`.
- `adaptive.py`: optional AdaptivePy adaptive sampling (`--sampling adaptive`). `msm.py`: adaptive sampling populations (Markov state model).
- `envcheck.py`: checks the platform and force-field files at startup. It first computes a two-atom system with the chosen platform; if that fails, it stops and explains the fix (for example the PTX error when the CUDA components are newer than the driver: install the matching `cuda-version`).
- `backends.py`: language-model backends (`claude -p`, `codex exec`, Anthropic API) that all return structured results. The claude backend removes `ANTHROPIC_API_KEY` from the environment so that it uses the Claude Code subscription login.
- `chat.py`, `chat_page.html`: the `chat` command, a local web page (`http://localhost:8765`), multiple chats, stored in `runs/.chats/`. The run card shows the computer name, full path, file list and download links (`/api/file`, `/api/download`; only files listed by `outputs.py` are served).
- `outputs.py`: lists the result files of a run (`protein.pdb`, trajectories, chi1 and bias data), plus the computer name and full path. Used by the command-line Summary and by the web page.
- `terminal.py`: terminal chat (`chat --terminal`) and the `start` menu (choices stored in `runs/.chats/start.json`).
- `llm.py`: the `ask` command and the settings form `RunPlan`. `ask` also uses `backends.py` and no longer needs an API key.
- `cli.py`: command line `start`, `run`, `resume`, `diagnose`, `check`, `info`, `fetch`, `ask`, `chat`, `report`, `compare`, `budget`, `experiment-a`, `shadow`.
- `core/`: the general decision core. It uses only the Python standard library and does not mention any observable, engine or system (checked by `tests/test_core_architecture.py`). `task.py` (task, each estimator's own requirements, budget, permissions), `evidence.py` (estimates, validity checks, shared signals), `registry.py` (estimators looked up by "kind × data type"; tool interface), `reasoner.py` (competing hypotheses, all marked as heuristic), `controller.py` (candidate actions, value, cost, permission and budget checks, selection), `ledger.py` (`decisions.jsonl`), `loop.py` (loop, checks before and after execution, continuation).
- `stability.py`: structural stability (RMSD, Rg, stationarity test, time spent near the starting structure, RMSD-Rg free-energy surface; results in `stability/`). `clustering.py`: GROMOS conformational clustering (results in `clusters/`).
- `backbone.py`: backbone φ/ψ for any residue: basin definitions (default alpha_R, beta including PPII, alpha_L, other; core-region margin 10°), per-frame basins, transition statistics (rate = count / residence time, Poisson error; mean residence time = total time / number of departures), free-energy surface (15° bins; error from the differences between replicas plus an error floor). Results are written to `backbone/` in the run folder.
- `tools_openmm.py`: OpenMM tools for the new core (`PlainMDTool` wraps `run_segment`; `MetadTool` wraps `run_replica` and rebuilds the bias potential to give weights) and featurization (chi1, distances, events; `event_series` is shared with `agent._diagnose_events`). The tools can look only at data up to a past moment (for replay). `shadow.py`: shadow mode (records the new core's decision each round; errors do not affect the run; `MDAGENT_SHADOW=0` turns it off), replay, and comparison with the original policy; command `shadow`.
- `estimators.py`: concrete estimators (unbiased populations, reweighted populations, Markov model populations, first-entry events); the numbers come from `uncertainty.py`, `msm.py` and `observables.py`. `synthetic.py`: tools for synthetic Markov chains with known answers, for development and testing.
- `.claude/commands/`: Claude Code project commands `/md` and `/md-status`.

Tests: `pytest -q tests` (about 4 minutes, includes tests that run a small peptide on the CPU); `pytest -q tests -m "not slow"` runs only the fast tests (320 tests, about 3 minutes; all tests about 15 minutes). Tests for structural stability and clustering are in `tests/test_stability.py`. Tests for the post-review revisions and the fixes from the independent review are in `tests/test_review_revisions.py`. Tests for backbone enhanced sampling are in `tests/test_backbone_enhanced.py`. Tests for backbone φ/ψ are in `tests/test_backbone.py` (rates and residence times are checked with 30 random seeds for calibrated errors). Tests for the general core are in `tests/test_core_*.py` and `tests/test_estimators.py` (about 7 seconds, all on synthetic systems). The adapter and shadow mode are tested in `tests/test_shadow.py` (with fake runs that have preset chi1 values; no MD). Tests run offline; UniProt sequences are in `tests/data/uniprot/`. Test system `examples/181L.pdb` (T4 lysozyme L99A with benzene; the Val111 side chain in the pocket rarely flips in conventional MD).
